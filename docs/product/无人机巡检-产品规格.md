# 商业级无人机电力巡检平台：产品与实施规格

> 文档类型：产品需求 + 实施路线基线
> 目标场景：输电线路与杆塔巡检
> 产品形态：三维优先的巡检任务仿真与管理平台
> 版本：V1 产品基线
> 说明：本文描述产品目标和验收要求，不代表已经实现；涉及真实无人机飞行的能力必须在完成设备适配、现场测试及相应安全/法规审查后才能启用。

> 与 `docs/architecture/无人机巡检.md` 是**两份不同的文档**：那份管分层与包边界，本文管业务闭环与验收。

## 1. 产品定位

### 1.1 产品目标

建设一个面向电力巡检流程的三维平台，让用户可以围绕真实业务对象完成：

**资产建档 → 巡检计划 → 航线规划 → 任务预检查 → 仿真/执行 → 数据采集 → 安全与质量检查 → 缺陷复核 → 报告归档 → 历史对比。**

V1 首先在现有 Three.js 场景和无人机模型基础上完成可运行的仿真闭环。产品结构要为后续连接真实无人机、影像分析和资产管理系统留出清晰接口，但不应为了未来可能的功能提前建成大量独立 Package。

### 1.2 与普通 3D 演示的区别

普通演示只需模型移动；商业巡检产品至少要能回答：

- 检查哪个资产、哪个部件？
- 本次任务要求采集什么证据？
- 任务规划是否完整，预计是否可执行？
- 每个检查点是否以正确距离、角度和传感器配置完成采集？
- 哪些点漏检、失败或存在安全风险？
- 照片、事件、巡检结果是否能够追溯到资产和任务？
- 同一资产在不同巡检周期之间发生了什么变化？

### 1.3 V1 的产品边界

V1 定位为 **无人机电力巡检任务仿真与验证平台**，优先完成三维场景、任务规划、自动执行、数据采集模拟、安全事件、结果和回放。

V1 不宣称替代真实飞控、专业航线审批、法定作业流程或人工专业诊断。仿真中的安全距离、续航和任务评分只是根据当前模型与配置计算的结果，不能直接当作真实飞行安全保证。

## 2. 商业巡检工作流

```text
资产台账
  ↓
制定巡检计划
  ↓
选择资产 / 部件 / 巡检模板
  ↓
生成巡检点和航线
  ↓
任务预检查与风险提示
  ↓
仿真预演 / 人工确认
  ↓
任务执行
  ↓
采集照片、遥测、轨迹和事件
  ↓
检查覆盖率与数据质量
  ↓
人工复核 / 缺陷登记
  ↓
生成报告并归档
  ↓
历史巡检对比 / 复检计划
```

**产品必须围绕资产和检查标准组织流程，而不能只围绕无人机和航点组织流程。**

## 3. 产品工作模式

V1 采用一个三维工作台、四种工作模式。场景始终保留，模式切换改变工具和浮层，不应反复销毁、重建整个三维场景。

### 3.1 场景 / 资产模式

目标：查看场景、管理资产、确认空间关系。

功能：

- 新建、加载、保存场景。
- 显示地形、电力线路、电塔、部件、无人机、障碍物和限制区域。
- 点击、悬停、选择、聚焦资产；三维视图与资产树同步选择。
- 查看线路、电塔及部件属性。
- 控制图层显示/隐藏。
- 支持 Orbit、Pan、Zoom、Fit to Scene、Focus Selected。
- 支持标签显隐、选择高亮、对象定位。
- 支持在场景中新增/编辑电力资产的基本属性；V1 可先使用已有模型和人工配置数据。

资产树建议：

```text
场景
├── 输电线路
│   ├── 杆塔 001
│   │   ├── 塔身
│   │   ├── 横担
│   │   └── 绝缘子组
│   ├── 杆塔 002
│   └── ...
├── 无人机
├── 障碍物
└── 限制区域
```

### 3.2 巡检任务 / 航线规划模式

目标：明确检查范围、检查标准和无人机的执行路线。

功能：

- 创建、复制、编辑、保存巡检任务。
- 选择无人机、线路、杆塔和部件。
- 选择巡检模板：杆塔重点部位、自定义巡检点、沿线巡检（V1 可按优先级分阶段实现）。
- 按模板生成 InspectionPoint；允许启用、禁用、排序、删除和补充巡检点。
- 为巡检点配置目标、期望拍摄距离、相对方向/航向、云台角度、采集类型和所需数量。
- 自动生成基础航线；支持新增、移动和删除航点。
- 设置起飞点、返航点、飞行高度、速度、巡检顺序和返航策略。
- 三维预览路线、巡检点、预计航程、预计耗时和预计能耗。
- 任务校验：资产是否存在、巡检点是否有效、路线是否完整、起降点是否设置、采集配置是否满足要求。
- 显示校验结果和可操作的错误定位；不能只给出“校验失败”。
- 保存任务版本，避免正在执行的任务因编辑而发生隐式变化。

V1 航线类型：

1. **Waypoint Route**：基础航点路线，必须实现。
2. **Tower Inspection Route**：围绕所选电塔生成若干检查点，V1 主场景。
3. **Corridor Route**：沿线路走廊检查，列入后续增强。
4. **Orbit / Vertical Scan / Terrain Following**：后续增强，不纳入首个可交付闭环。

### 3.3 巡检执行模式

目标：把任务过程、三维状态和安全信息清晰地呈现出来。

功能：

- 开始、暂停、继续、终止任务。
- 仿真速度控制：0.5x、1x、2x；4x 可作为调试选项。
- 显示任务阶段、当前巡检点、总进度、已完成/失败/跳过数量。
- 显示无人机位置、高度、速度、航向、电量、状态和实际轨迹。
- 无人机自动起飞、导航、接近目标、调整云台、模拟拍照、转到下一个点、返航和降落。
- 每个巡检点执行距离、航向、云台和采集检查，并明确显示通过或失败的原因。
- 安全监测与任务执行并行，不得只在任务结束后统计风险。
- 展示最新照片/截图、拍摄目标和采集时间。
- 点击事件或告警，三维相机定位到对应位置。
- 支持自由视角、跟随无人机、跟随目标、巡检相机视角。
- V1 支持简单人工暂停/跳过巡检点；手动接管可列为 V1.1，真实设备接管必须另行验证。

### 3.4 巡检结果 / 回放模式

目标：让用户判断任务是否完成、证据是否充分、风险发生在哪里。

功能：

- 查看任务结论、耗时、巡检点完成情况、覆盖率、照片数量、数据完整率、能耗和违规统计。
- 在三维场景中为检查点显示 Passed、Warning、Failed、Skipped 状态。
- 浏览照片/模拟采集图像，并查看其任务、资产、部件、检查点、时间和无人机位置。
- 查看事件与告警，点击后定位到对应时间与空间位置。
- 查看航迹和任务阶段时间轴。
- 回放支持播放、暂停、停止、拖动时间轴和倍速。
- 回放支持跟随无人机、跟随目标和自由视角。
- 输出可保存/导出的巡检报告。
- V1 仅提供缺陷的人工登记/复核入口；自动缺陷识别列入后续版本。

## 4. 核心业务对象与业务语义

V1 只定义业务真正需要的对象，避免为了架构完整而创建过多抽象。

| 对象 | 职责 | 关键字段/信息 |
|---|---|---|
| Scenario | 一份可保存的三维场景定义 | id、name、terrain、environment、assets、obstacles、restrictedZones |
| PowerLine | 一条输电线路 | id、name、voltageLevel、geometry、towerRefs |
| PowerTower | 一座电塔资产 | id、name、position、height、towerType、lineId、componentRefs |
| AssetComponent | 电塔的可检查部件 | id、assetId、componentType、position、orientation、modelRef |
| DroneDefinition | 无人机能力定义 | id、model、maxSpeed、maxAltitude、batteryCapacity、cameraCapabilities |
| MissionDefinition | 一份可重复执行的任务定义 | id、name、droneId、targetRefs、inspectionPoints、route、rules、cameraConfig |
| InspectionPoint | 一次具体检查目标 | id、targetId、position、order、requirement、enabled |
| InspectionRequirement | 检查有效条件 | distanceRange、headingTolerance、gimbalTolerance、captureRequirement |
| Route / Waypoint | 规划路径及导航点 | routeType、waypoints、altitude、speed、heading、actions |
| MissionRun / Session | 某次任务执行实例 | id、missionVersion、status、startTime、endTime、runtimeState |
| MediaAsset | 采集证据的统一索引 | id、type、uri、timestamp、agentId、missionRunId、targetId、pointId、pose、metadata |
| InspectionPointResult | 单个检查点结果 | pointId、status、errors、captureIds、violations |
| SafetyEvent | 发生过的安全事件 | type、severity、timestamp、location、agentId、targetId、actionTaken |
| Finding | 人工确认/后续 AI 生成的缺陷记录 | id、assetId、componentId、severity、description、evidenceIds、reviewStatus |
| InspectionReport | 面向交付的任务报告 | summary、coverage、findings、safety、mediaRefs、recommendations |

### 4.1 关键概念必须分开

- **资产**：被检查的电力设施。
- **InspectionTarget**：资产中的检查目标或部件。
- **InspectionPoint**：任务中一次具体的检查动作及其要求。
- **Waypoint**：导航路径上的位置，不自动等于一个检查任务。
- **MissionDefinition**：可重复使用的任务计划。
- **MissionRun / Session**：该计划的一次具体运行。
- **MediaAsset**：照片/视频/截图等证据文件及关联元数据。
- **Finding**：经人工复核或后续算法识别出的异常/缺陷；照片不等于缺陷。
- **Report**：把执行过程、证据、检查结论和缺陷摘要组织成可交付结果。

## 5. 巡检任务规则

### 5.1 检查点有效条件

一个检查点不能仅因为无人机经过附近就算成功。至少根据任务配置校验：

- 是否到达允许的位置范围。
- 与目标的实际距离是否在要求范围内。
- 航向/相对观察方向是否在容差范围内。
- 云台方向是否满足要求。
- 是否成功产生所需数量的采集证据。
- 证据与目标、检查点、任务运行实例是否正确关联。

每项条件都应能独立解释失败原因。

### 5.2 点位状态

```text
Pending
  → Approaching
  → Inspecting
  → Passed / Warning / Failed / Skipped
```

失败策略需明确配置。V1 默认记录失败并继续后续点位，避免一个检查点失败导致整个任务无期限卡住；任务结束后在结果页明确列出未完成项。

### 5.3 任务状态

```text
Draft → Ready → Running ↔ Paused
                    ├→ Completed
                    ├→ Aborted
                    └→ Failed
```

只有通过任务校验的任务才能进入 Ready。Completed 不代表所有点均通过，结果中还必须给出 Passed / Warning / Failed / Skipped 统计。

## 6. 安全与任务预检查

### 6.1 V1 仿真安全检查

至少包含：

- 最小安全距离（无人机与线路、电塔或指定目标）。
- 障碍物碰撞/近碰检查。
- 禁飞区或限制区域。
- 最大飞行高度。
- 电量阈值与返航触发。
- 可选风速限制（V1 使用简化环境参数）。

### 6.2 安全事件必须可追溯

每次事件至少记录：

- 事件类型和等级。
- 发生的仿真时间和 Tick。
- 无人机、任务运行实例、目标资产。
- 事件位置、测得值、阈值。
- 采取的处置动作。
- 是否已恢复/关闭。

### 6.3 安全策略

| 事件类型 | V1 建议动作 |
|---|---|
| 接近安全距离阈值 | Warning，继续执行并记录 |
| 严重安全距离违规 | Critical，按任务策略暂停或返航 |
| 碰撞 | 记录 Critical，并按配置暂停/终止；仿真中不得隐去碰撞事实 |
| 进入限制区域 | 记录事件并触发配置动作 |
| 低电量警告 | 提醒，并估算剩余任务可行性 |
| 低电量返航阈值 | 触发 Return-to-Home 仿真流程 |
| 任务/设备异常 | 暂停或 Failed，并保留完整日志 |

注意：这些规则用于仿真验证。真实飞行中的最小距离、禁飞区、高度限制和应急动作必须依据实际机型、作业环境、当地法规及运营规程配置，并经过现场验证。

## 7. 数据采集与质量管理

### 7.1 采集类型

V1：

- 照片或三维场景截图。
- 采集时间。
- 无人机位置与姿态。
- 目标资产和部件。
- 对应 InspectionPoint。
- 采集成功/失败原因。

后续可扩展视频、热红外、LiDAR 等，但不能在 V1 中把模拟截图标记成真实相机影像。

### 7.2 证据关联

每个 MediaAsset 至少关联：

```text
MissionRun
  ├── Agent
  ├── InspectionPoint
  ├── Target Asset / Component
  ├── Capture Time
  ├── Capture Pose
  └── Media File
```

### 7.3 数据质量

至少评价：

- 要求的照片数量是否满足。
- 照片是否成功生成并可打开。
- 目标关联是否完整。
- 拍摄位置/角度是否满足配置要求。
- 必须巡检的点是否全部有结论。

V1 的“有效照片”只能依据当前能验证的条件判断，不应声称已经达到真实影像清晰度、缺陷可辨识度或专业诊断标准，除非未来增加经过验证的成像模型和检测方法。

## 8. 缺陷与维修闭环

商业巡检不能止于照片数量。V1 可先建立人工复核闭环，为后续 AI 识别留出空间。

### 8.1 Finding 基础功能

- 从照片或巡检点创建 Finding。
- 关联线路、电塔、部件和证据照片。
- 设置类型、严重等级、描述和建议。
- 设置状态：待复核、已确认、误报、待处理、已处理、已复检。
- 支持人工修改和审计记录。

### 8.2 后续闭环

```text
采集证据
  ↓
人工复核 / AI 建议
  ↓
确认 Finding
  ↓
维修任务或工单（后续集成）
  ↓
修复后复检
  ↓
对比前后证据
```

V1 不需要先实现完整工单系统，但 Finding 与资产、媒体和历史巡检必须采用稳定关联。

---

## 9. 历史巡检与资产历史

商业使用需要重复巡检。对于同一资产，系统应该保存多次运行记录，并允许查看：

- 最近一次巡检时间。
- 历史巡检记录及报告。
- 历次巡检点覆盖情况。
- 历史 Finding 与处理状态。
- 同一目标的历史照片。
- 资产状态变化。

V1 可以先提供“历史任务列表 + 同一目标的照片/结果对照”。自动视觉变化检测属于后续能力。

任务计划修改时创建新版本，不覆盖已经执行任务的历史定义。每次 MissionRun 必须记录实际执行的 MissionDefinition 版本。

## 10. 报告与导出

V1 报告至少包含：

1. 任务基本信息：任务编号、名称、线路、无人机、时间、执行状态。
2. 任务摘要：巡检点总数、通过/警告/失败/跳过数、完成率。
3. 数据统计：采集数、有效采集数、数据完整率。
4. 安全统计：碰撞、距离违规、限制区域、高度、电量等事件。
5. 飞行统计：时长、航程、起止电量（注明为仿真值或真实设备数据）。
6. Finding 列表：资产、部件、严重等级、说明、证据和建议。
7. 关键照片和空间位置。
8. 任务轨迹/三维结果截图。
9. 结果结论与未完成项。

格式：V1 至少支持浏览器内报告页面和 PDF/打印友好导出之一；数据导出可提供 CSV/JSON。报告必须明确数据来源为 Simulation、真实设备或人工录入，不能混淆。

## 11. 三维交互与视觉要求

三维是核心工作区，不是放在管理后台中的装饰性画布。

### 11.1 需要表达的空间对象

- 线路、电塔及部件。
- 无人机当前模型和朝向。
- 当前巡检点、已完成点、失败点和跳过点。
- 规划航线、当前航段、历史轨迹。
- 相机 Frustum/观察方向。
- 安全区域、障碍物、告警位置。
- 拍摄位置与照片关联。

### 11.2 四种模式的三维重点

| 模式 | 三维主内容 | 主要操作面板 | 底部区域 |
|---|---|---|---|
| 场景/资产 | 地形、线路、杆塔、部件 | 资产属性、图层 | 场景状态 |
| 任务/规划 | 目标、巡检点、航线、起降点 | 任务参数、检查要求 | 航程/时间/能耗估算、校验问题 |
| 执行 | 无人机、当前目标、轨迹、相机方向、告警 | 遥测、当前检查点、安全事件 | 任务时间轴与事件 |
| 结果/回放 | 状态化巡检点、航迹、照片/告警位置 | 结果详情、证据、Finding | 回放时间轴/事件列表 |

### 11.3 视觉反馈

| 用户操作/事件 | 必须反馈 |
|---|---|
| 选择线路/电塔 | 高亮、聚焦、显示属性 |
| 生成巡检点 | Marker 出现并可选择 |
| 生成/修改航线 | 路线即时更新 |
| 开始执行 | 状态变化，无人机起飞 |
| 到达当前点 | 当前点高亮并显示检查进程 |
| 采集成功 | 显示采集完成，建立照片 Marker |
| 检查失败 | 显示原因并标记失败点 |
| 安全事件 | HUD 告警、三维事件标记、时间轴事件三者关联 |
| 点击照片/事件 | 相机定位到相关空间位置 |
| 拖动回放时间轴 | 无人机、路线状态和事件同步变化 |

### 11.4 相机模式

V1：

- Free：自由视角。
- Follow Drone：跟随无人机。
- Follow Target：跟随当前目标。
- Inspection Camera：查看无人机相机模拟视角。

镜头过渡应平滑，不能在每个巡检点间突然瞬移；用户可以随时切回 Free。

## 13. 商业级质量要求

本节目标是产品验收基线，不是对现有系统的性能声明。所有数值应通过基准场景测试确认，并根据运行硬件调整。

### 13.1 正确性与可追溯性

- 任何任务运行都具有唯一 `MissionRunId`。
- 所有照片、事件、点位结果都能追溯到任务运行实例。
- 已执行任务的配置和结果不可因后续编辑而被覆盖。
- 任务结束时必须明确标注 Completed、Aborted 或 Failed。
- 结果区分仿真数据、真实遥测、人工录入数据。
- 告警、检查点、照片和报告之间的关联可双向定位。

### 13.2 可恢复性

- 页面刷新或意外关闭后，已保存的任务定义和已完成的运行记录不能丢失。
- 任务运行中断时，应能标记中断原因；V1 可不支持从任意 Tick 精确恢复，但不能把未完成任务伪装成 Completed。
- 文件加载失败、模型缺失、照片读取失败时应显示明确错误和可执行建议。

### 13.3 性能目标

建议使用固定验收场景：1 条线路、5 座电塔、每塔 3 个检查点、1 架无人机、若干障碍物。

- 标准场景持续交互目标 ≥30 FPS；简单场景目标 60 FPS。
- 任务状态变化后，UI 应在 200ms 内体现（不含人为设置的模拟延迟）。
- 常用资产选择/聚焦应在 100ms 级给出视觉反馈。
- 20Hz 轨迹采样作为 V1 可选基线；实际采样频率需兼顾数据量与回放精度。
- 长时间运行测试期间不得出现持续性内存增长；具体阈值通过固定环境测试确认。

### 13.4 可用性

- 任务校验失败时指出具体字段/点位和修正方式。
- 危险操作（终止任务、覆盖保存）需要确认或提供撤销策略。
- 状态必须同时使用文字/图标，不只依靠颜色表达。
- 空状态、加载状态、失败状态和无数据状态均有明确页面反馈。

### 13.5 测试

- 路线生成和检查点评价需要单元测试。
- Mission 状态机需要覆盖正常、暂停、终止、失败和漏检分支。
- 安全规则需要边界值测试。
- 固定场景需进行重复任务测试，确认同一输入可获得等价结果。
- Replay 关键时刻应与事件时间和轨迹数据对应。
- 导出报告的汇总值必须与结果页一致。

- 点位结果、事件记录、采集证据关联。
- 任务统计、结果三维标记和基础 Replay。

## 15. V1 验收用例

### 用例 A：正常巡检

测试场景：1 条线路、5 座电塔、每塔 3 个检查点、1 架无人机。

验收：

- 可以创建并保存任务。
- 能够生成并预览 15 个巡检点及对应航线。
- 无人机按路线执行并生成采集结果。
- 每个点均显示 Passed / Warning / Failed / Skipped 之一。
- 结果页显示完成率、照片数、耗时和能耗。
- Replay 能显示无人机轨迹和关键事件。

### 用例 B：检查点漏检

- 禁用或移除一个检查点，或故意让该点不能满足采集要求。
- 结果不得显示 100% 完整覆盖。
- 结果页能定位该点并说明失败/跳过原因。

### 用例 C：安全距离违规

- 设置一个会触发安全距离规则的测试航线。
- 系统生成具有时间、位置、无人机、目标、测量值和阈值的安全事件。
- 执行页和结果页均显示该事件。
- 点击事件可以定位到三维位置和回放时刻。

### 用例 D：低电量返航

- 将初始电量或消耗参数设置为能够触发返航的测试值。
- 系统记录触发原因并执行返航流程。
- 任务结果清晰标注是否完成、是否中止及未完成点位。

### 用例 E：采集失败

- 模拟相机采集失败或要求的照片数量不足。
- 不得把该巡检点标记为 Passed。
- 失败原因、命令/事件记录和任务结果之间可追溯。

### 用例 F：历史记录

- 同一个 MissionDefinition 执行两次。
- 产生两个独立 MissionRun。
- 修改任务定义后，旧运行记录和报告保持不变。

### 用例 G：报告一致性

- 报告中的巡检点数量、照片数量、违规统计、耗时和评分与结果页面一致。
- 报告明确标识数据来源是仿真、真实设备或人工录入。

## 16. 现阶段不做的功能

为控制首个版本范围，暂不作为 P0：

- 高精度空气动力学和真实飞控仿真。
- SLAM、视觉定位、完整自主避障规划。
- AI 缺陷识别、自动缺陷定级和自动维修决策。
- 热红外、LiDAR、多光谱的高保真传感器仿真。
- 多无人机协同与无人值守 Dock。
- 完整企业工单/ERP/SAP 系统。
- 大规模云端仿真调度。

这些能力可以在 P2/P3 阶段逐步引入，但不应阻碍 V1 完成巡检闭环。

## 17. 推荐实施顺序

1. **先把页面主流程跑通**：四种模式之间可以切换，三维场景保持连续。
2. **做资产与任务定义**：线路、电塔、部件、检查点和任务模板。
3. **做路线生成和预检查**：能看见路线，能知道为什么不能执行。
4. **做任务执行**：无人机运动、点位状态和仿真时间运行一致。
5. **做证据关联**：每个采集结果都能追溯到资产、任务和点位。
6. **做安全事件**：事件不仅提示，还进入时间轴、结果和回放。
7. **做结果与报告**：把一次运行归档成可交付成果。
8. **做历史与 Finding**：逐步形成资产级的长期巡检记录。
9. **最后接真实设备和 AI**：以 Adapter 和稳定业务接口接入，不让真实设备协议污染巡检业务模型。

实现原则：**逻辑上模块化，第一阶段不强求把所有模块拆成独立 npm Package。** 只有当第二个业务场景或真实复用需求出现时，再把稳定能力提取为独立包。

## 19. 最终成功标准

商业级巡检产品的第一步，不是一次性堆满所有高级功能，而是可靠地完成一个可复现、可追溯、可解释的端到端流程：

> 用户能够围绕电力资产创建巡检任务，在三维场景中规划和预演航线，执行无人机巡检仿真，检查每个点是否有效采集，追踪安全事件，归档照片和运行记录，生成可交付报告，并在三维回放中定位任何关键结果。

在这个闭环稳定之后，再扩展真实无人机、AI 缺陷检测、历史变化分析、周期调度和企业系统集成。
