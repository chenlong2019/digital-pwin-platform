# 园区点云沙盒

无人机沙盒 `/` 使用 `D:\cpp-projects\points-viewer` 示例中的 campus-road v2 园区。园区范围约 284 × 238 米，原始最高精度约 3830 万点；场景不缩放，保持米制。汽车和电网场景继续使用自己的场景配置。

## 使用

- **园区全景**：浏览完整园区，拖动旋转、滚轮缩放。
- **聚焦无人机**：回到南侧道路上的无人机附近。
- **跟随 / 机载**：使用原有飞行和云台视角；拍照、录像与点云共用同一个 Three 场景。
- **场景 → 显示避障范围**：显示从点云生成的简化范围，默认隐藏。

首次打开直接读取随应用发布的 606,306 点概览（gzip 约 1.67 MB）。视角靠近后，从示例的点云服务补充更细的分块。细节下载失败时保留概览并显示重试入口。默认显示预算为 250 万点，缓存预算为 500 万点，最多同时下载 4 个分块；离开页面会取消请求、关闭解码线程并释放显存。

细节服务地址可通过构建环境变量 `VITE_CAMPUS_POINT_CLOUD_URL` 配置。默认地址与示例相同：`http://49.235.216.125/pointcloud/campus-road-points-v2-spacing-fix`。部署到 HTTPS 时应配置支持 HTTPS 的数据地址或同源代理；设置为空字符串可只使用内置概览。

## 数据与坐标

索引与概览位于 `apps/drone-simulator/public/scenes/campus-road/`。从本地示例重建：

```powershell
node scripts/prepare-campus-scene.mjs D:\cpp-projects\points-viewer\public\data\campus-road-v2
```

脚本合并各独立分块的 LOD3，生成概览、索引和应用层的 `campus-layout.json`，无需复制完整的约 181 MB 数据。索引里的共享流偏移不能用于独立分块；独立分块始终从字节 0 开始解码。每点 9 字节，前三个 Int16 为局部坐标，后三个 UInt8 为 RGB。对 gzip 按文件头判断，兼容服务已解压的响应。

源坐标是东 / 上 / 北，平台坐标是东 / 上 / 南。源数据中的 `[0, 0.035, -105]` 映射到平台原点，也是南侧道路起飞点，照片登记和飞行回放使用场景标识 `campus-road-points-v2-spacing-fix`。

点云解码与 LOD 选择参考 `points-viewer/lib/pc/campus.ts` 和 `campus-lod.ts`；渲染使用适配现有 WebGL 的圆形点精灵，共享材质与概览覆盖掩码。相机细节调度包含当前显示视角和拍照 / 录像所用的云台视角。

## 当前精度边界

366 个碰撞代理由 LOD3 中高于 2.5 米、每个 4 米网格至少 3 个样本的点生成。顶部向上取整到 5 米，再合并相邻等高网格。物理避障和渲染雷达使用同一批范围，未使用旧测试场景的障碍物。这是保守的建筑与绿化近似，不能等同于逐点碰撞；低矮物体、薄构件和悬空通道仍需后续专门建模。地面按起飞点高度处理，尚无地形跟随。

源数据包含合成的立面补点，提升外观密度，不代表新增测绘信息。当前接入的是点云场景，还不是训练后的 3D Gaussian Splatting / NeRF 渲染。
